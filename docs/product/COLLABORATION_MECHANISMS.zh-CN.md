# 协作机制

[English](COLLABORATION_MECHANISMS.md) · **简体中文**

这些机制让智能体辅助的项目工作更容易恢复、验证和共享。真实用户、公司、客户、机器路径、当前工作、凭据和未公开项目事实，应保存在私人工作流中心或项目仓库中。

## 公开内容边界

公开可复用的规则，而不是催生规则的私人事件。

可以公开：

- 通用工作流规则、模板、验证关卡和示例；
- 适合公开的命令名称和占位路径；
- 经脱敏、可能发生在任何用户身上的失效模式；
- 公开文档链接或独立编写的指导。

不得公开：

- 私人姓名、邮箱、账号、机器名、路径或远程地址；
- 公司、客户或内部项目细节；
- 凭据、令牌、含秘密的截图或私人日志；
- 当前工作状态、私人待办或未公开产品事实。

## 机制清单

| 机制 | 何时使用 | 公开实现方式 |
| --- | --- | --- |
| 编号待办队列 | 请求含多个独立事项，或待办较长 | 显示简洁编号列表，同一轮保持编号稳定，逐项标记完成、暂停、阻塞或延后。 |
| 完成闭环记录 | 准备宣布任务完成 | 核对当前指针、对应待办、工作项状态、验证证据、相关运行副本和残余风险。已完成工作不能继续作为默认恢复目标。 |
| UTF-8 与乱码防护 | 编辑含非 ASCII 文本的 Markdown、技能、提示词、模板或状态文件 | 明确使用 UTF-8 读写，提交前查找替换字符和常见乱码，不能把终端乱码复制到长期文件。 |
| 渐进加载上下文 | 恢复、审计或修改项目 | 从最小定位状态开始，仅在风险、歧义、未提交修改或公开同步需要时扩展到项目级或完整读取。 |
| 微命令路径 | 用户输入 `TODO`、`status`、`checkpoint` 等准确指令 | 定义最小可靠文件或命令路径；状态没有歧义时，不将微命令扩展成全项目扫描。 |
| 长期经验沉淀 | 反馈重复出现，或错误揭示可复用的失效模式 | 将经验转成规则、模板、脚本、测试用例或待办。仅有聊天记录不算长期记忆。 |
| 公开与私人事实来源分离 | 共享起步包，同时保留个人状态 | 公开起步包保存通用技能、脚本和模板；私人中心保存配置、注册表、当前工作和偏好；项目仓库保存项目事实和交付物。 |
| 公开同步扫描 | 复制、发布、推送或准入公开候选包前 | 扫描凭据、私人路径、私人域名、个人标识和内部项目名。远程秘密扫描或推送保护是补充，不能替代本地审核。 |
| 验证与残余风险交接 | 结束一轮工作或交给其他智能体 | 说明执行的命令、结果、未检查内容及原因、剩余风险、下一负责人，并区分本地提交与远程推送。 |
| 稳定专家角色与运行实例分离 | 使用专家、审核者或子智能体 | 将稳定角色写成可复用约定；平台昵称或运行 ID 只作为当次追踪证据。 |
| 命名与变体一致性 | 工作流标签、仓库、技能或内部包改名 | 保持清晰映射，记录别名或迁移，不将内部变体后缀混进用户可见恢复提示词。 |
| 最小仓库约定 | 向其他用户共享起步包 | 提供 README、许可证、贡献或维护指南、安全与私人数据说明，以及明确的安装或快速开始路径。 |
| 源文件、运行与引导副本 | 工作流会安装生成的运行副本 | 源文件是权威，运行目录是加载副本，引导副本用于恢复。同步有要求时比较文件清单或哈希。 |
| 有边界的自主执行 | 用户要求长时间或无人值守运行 | 开始前明确目标、停止条件、验证频率、授权边界和检查点路径。 |

## 采用检查清单

宣布可复用工作流改进完成前：

1. 将通用规则放进正确的公开载体：技能、模板、文档或验证脚本。
2. 不在公开文字里放个人或公司专属示例。
3. 项目维护多个起步包时，检查对应变体。
4. 对修改文件运行适用的公开扫描与编码检查。
5. 报告验证证据、残余风险、本地提交状态和待推送或发布状态。

## 参考背景

这些机制为 q-workflow 独立实现，其防护方式与公开文档及常见工具行为一致：

- GitHub 仓库指导将 README、许可证、贡献和安全指南作为帮助用户与贡献者建立预期的资料。
- GitHub 秘密扫描和推送保护用于阻止受支持的凭据模式进入仓库。
- Microsoft 说明 Windows PowerShell 与较新 PowerShell 的默认编码不同；明确使用 UTF-8 可避免许多跨终端问题。
- Git 的 porcelain 状态格式面向稳定的脚本读取。
