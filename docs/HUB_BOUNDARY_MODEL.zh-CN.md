# 工作流中心边界模型

[English](HUB_BOUNDARY_MODEL.md) · **简体中文**

大多数用户只需要一个私人工作流中心仓库。

公开的 `q-workflow-hub` 起步包提供安装程序和源文件。私人工作流中心则是保存项目定位和恢复状态的日常状态仓库或文件夹。项目专属源码和长期记忆保存在各自的项目仓库中。

通常只需一个工作流中心；仅在确有需求时配置额外变体。

## 1. 私人工作流中心

用途：

- 保存用户的当前工作指针、项目注册表、TODO、日志和生成的助手配置；
- 跨设备恢复工作状态；
- 将本机路径和偏好保持私有。

规则：

- 需要备份或跨设备同步时，大多数用户使用一个私人 Git 远程仓库即可。
- 可以包含本机路径和私人工作流状态。
- 不应变成公开产品包。
- 拉取或更新前，先通过仓库定位检查，再进行 Git 操作。
- 运行配置 `.codex/q-profile.json` 的 `hub` 应指向此中心，并通过 `repositories` 记录已知项目和起步包仓库。

## 2. 公开起步包

用途：

- 提供可复用的安装脚本、模板、文档、技能和入门资料；
- 为新用户生成私人工作流中心；
- 可以在目标读者范围内共享。

规则：

- 不得保存当前任务状态、私人项目事实、凭据或仅适用于某台机器的恢复指针。
- 应包含 `scripts/resolve-workflow-repo.ps1` 和 `scripts/repo-locator-smoke.ps1`，让生成的工作流中心能恢复仓库位置。
- 安装程序可以写入用户生成的 `q-profile.json`，但起步包本身不是用户的当前工作状态。
- 推广或推送前，必须完成公开内容安全检查、安装冒烟测试和仓库定位冒烟测试。

## 3. 项目仓库

用途：

- 保存项目专属源码、任务、决策、验证证据和接续提示词；
- 避免项目产物塞满工作流中心。

规则：

- 项目事实属于项目仓库。
- 工作流中心只保存定位信息和当前工作指针。
- 起步包保存模板与可复用工作流逻辑。

## 仓库定位边界

仓库定位检查按以下步骤跨越这些层级：

1. 工作流中心或运行配置提供候选映射。
2. 起步包提供可复用的解析工具和安装逻辑。
3. 只有 `.git` 与远程地址匹配，才接受项目仓库身份。

解析成功只意味着“这个路径是目标 Git 仓库”，不意味着“可以发布这个仓库”，也不意味着“私人工作流状态应进入起步包”。
