# 工作流标准化：兼容性检查清单

[English](workflow-standardization-ledger-20260701.md) · **简体中文**

历史候选方案参考，日期为 2026-07-01。当前包状态请查看[版本说明](../releases/q-workflow-v1.2.zh-CN.md)。

## 采用标准前的检查

| 方面 | 兼容性关注点 | 必需检查 |
| --- | --- | --- |
| 项目结构 | 目录命名与迁移影响 | 移动现有项目前审核结构参考。 |
| 结构审计器 | 过多警告与小任务行为 | 检查严重程度，运行配置样本，包括宽松模式。 |
| 专家分派 | 委派前须明确角色与运行实例的映射 | 标准检查和真实专家审核场景。 |
| 输出状态行 | 路由、动作与状态不能混写 | 标准检查和对话场景。 |

## 维护经验

- 为文字规则配套严重程度、检查和明确阻塞项。
- 示例中区分路由标识、专家角色与任务状态。
- 在委派前建立角色与运行实例映射。
- 明确哪些警告会阻止交付。
- 生命周期检查通过前，不将草稿标准当作稳定标准。

## 采用检查清单

1. 运行标准检查器自测。
2. 对受影响的 q-workflow 技能运行检查器。
3. 对修改的 Markdown 和 Python 文件运行编码检查。
4. 对受影响仓库执行 `git diff --check`。
5. 取得独立的文档或工作流审核，修复并重新检查阻塞项。
6. 说明剩余限制，区分验证、同步、迁移和发布；每项动作都需要自己的范围和授权。

只审核预定范围的修改。标准更新不代表允许移动无关文件、广泛同步副本或公开推送。
