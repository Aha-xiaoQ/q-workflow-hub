# 项目结构 v2：迁移说明

[English](project-structure-v2-review-20260701.md) · **简体中文**

历史设计参考，日期为 2026-07-01。安装和选择包版本请使用[当前快速开始](../../QUICKSTART.zh-CN.md)。

## 目的

文档、演示文稿、软件、固件、硬件和外部源码项目需要可恢复的布局，同时保持小任务轻量。

此设计遵循仓库级 README 和共享忽略规则，将输入、工作材料、输出与环境说明分开，并保留 Zephyr 应用、KiCad 项目文件、Python 包等工具原生结构。

## 布局与检查

- 生命周期目录从 `00-project/` 编号到 `06-handoff/`，另设 `90-archive/` 和被忽略的 `99-local-state/`。
- `skills/` 与 `.gitignore` 保留在根目录。
- `00-project/` 用于项目治理，不是杂项输出箱。
- 工具原生布局保留在各配置对应的 `03-work/` 子树中。
- 设计支持的配置包括 `document-only`、`research-deck`、`software-tool`、`firmware-board`、`hardware-design`、`external-based` 和 `workflow-or-skill`。
- 结构审计检查目录、忽略规则、项目本地技能命名及配置路径；分阶段迁移时，对旧根目录发出警告。

可执行的工作流指导见[技术结构参考](../../skills/q-workflow/references/project-structure.md)（英文）。

## 迁移保护措施

现有项目应分批审核迁移，不做一次性大重组。小型一次性任务可使用 `--relaxed` 审计模式，并在项目 README 中记录延后创建的空目录。保留软件、固件与硬件原生布局，确保工具仍能打开项目。

在应用到现有工作前，用标准检查器、编码检查和实际配置样本验证结构变更。

## 外部文件夹接入

采用外部文件夹前，检查来源或上游、Git 状态、未提交及未跟踪文件、隐私与许可证限制、工具原生根目录，以及接入方式。

- 外部文件夹成为活跃源文件时，优先移动或克隆并保留历史。
- 只有审核过的未版本化或有未提交修改的副本，才使用复制快照，并附来源清单。
- 上游或供应商示例需要持续同步时，使用子模块、子树或清单引用。
- 只有工具或组织约束要求源文件留在别处时，才仅使用链接访问，并在私人记录中保存准确恢复路径。

源文件位于仓库中，或者有准确清单能重建或定位源文件，项目才算可恢复。
