# Auto Dispatch Policy

Use only when delegation mode or required independence is unclear. Ordinary
dispatch is owned by `../workflows/dispatch-agent.md`.

## Decide by evidence value

- Honor user and host constraints first. Select a stable role for an explicit
  specialist request. Spawn for an explicit subagent/independence request,
  required independent gate, useful context isolation, or disjoint parallel work.
- A nontrivial code/rule review is a good candidate for an independent reviewer.
  Complexity alone does not require several agents. Tiny deterministic edits
  need only their normal checks. A main-agent check is never independent.
- For ordinary local work with no useful independent scope or available tool,
  a local check suffices with an honest evidence limit. A required independent
  domain/release gate remains pending until met.
- Reviewers are read-only unless assigned a repair scope. Writers have disjoint
  paths and main owns integration. Reuse a reviewer rather than restarting the
  same question with another agent. Follow the host's concurrency limits.
- Permission depends on the action's scope, not the agent's existence. Existing
  authorization counts; ask only for missing, revoked or exceeded authority.
  Do not auto-delegate credentials, publication or destructive changes.

## Visible identity and compact contract

Announce the role, mission and permissions before spawning. One readable update
may cover distinct agents. Stable role identity uses English alias plus Chinese
name; Run instance is the actual returned handle, recorded once in evidence.
Compact instructions require goal, scope/actions, acceptance/stop and output;
results require findings, evidence and gaps. They do not require duplicate
English name / Chinese name fields, a card per tool call, identity-only turns,
or unused error/learning/capacity fields. Report a failed spawn and choose a
retry only when useful; keep its resulting identity accurate.

Missing authority or verification blocks the dependent action; cosmetic packet
differences can be normalized by the parent. Formal consumer schemas still apply
when selected by `handoff-protocol.md`.

## Review and finish

Independent release/domain evidence precedes the governed acceptance or publish
claim. Preserve useful reports and finding dispositions in the existing work
item; separate files only for bulky evidence. Apply accepted fixes and rerun
invalidated checks. Complete authorized delivery without a second permission
round. An ordinary review does not authorize a global skill rewrite.

For a requested delegation-policy audit, compare independence value, useful
findings and overhead. No scorecard or durable lesson is required per dispatch.
