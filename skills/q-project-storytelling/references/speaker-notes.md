# Speaker Notes

Use this reference when the visible artifact exists but the presenter notes
feel flat, repetitive, or too generic.

## Notes Are Not Slide Text

Speaker notes should help the presenter explain, transition, and handle
objections. Avoid notes that simply restate every bullet.

## Five-Part Note Pattern

For each substantive slide, write:

1. **Purpose**: why this slide exists in the story.
2. **Core message**: the one sentence the audience should remember.
3. **Concrete example**: a real or realistic example that makes it tangible.
4. **Objection or risk**: what the audience might question and how to frame it.
5. **Transition**: why the next slide follows.

For short slides, combine purpose and core message. For section dividers, use
only transition and framing.

## Talk-Track Levels

- 30-second version: what to say if time is short.
- 2-minute version: normal presentation track.
- Backup detail: technical explanation or evidence if challenged.

Keep backup detail in notes or appendix, not on the visible slide unless the
audience needs it to understand the main argument.

## Quality Checks

- Does the note add something not already visible?
- Is there one concrete example every 2-3 slides?
- Does the note explain why the audience should care?
- Does it prepare the next slide?
- Does it avoid internal production comments such as "this draft" or "fix
  later" unless the deck is explicitly a review artifact?

## Common Fixes

- If notes are too generic, add one audience-specific objection.
- If notes are too long, move backup detail into a separate appendix or report.
- If notes feel like marketing, add proof and a limitation.
- If notes feel like a technical dump, add the user's pain and the next action.
