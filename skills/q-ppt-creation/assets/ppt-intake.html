QPPT IntakePublic Runner
静态页面只导出 `q-ppt-intake/v1` JSON。Agent 或本地 runner 才负责 story brief、slide map、PPTX、视觉审查和最终打开。

基本请求

先把 PPT 请求变成可复用的 JSON，而不是在浏览器里直接生成 PPT。

Static: exports JSON only

这份 PPT 要解决什么问题？

首屏只收集请求边界：标题、受众、目的、交付方式和页数合同。

Request boundary
Public static mode 不读取本机完整路径，也不直接调用生成器。它只复制或下载 JSON；后续由 Agent/runner 接手。你填写的文本会进入 JSON；敏感或专有内容只在下游 runner 已获准时填写。

有哪些材料和故事约束？

用结构化条目记录文件、链接、现有 deck、证据点和待补缺口。

Source contract

结构由谁决定？

自动模式只记录目标 section 数；手动模式记录 section 名称，不把示例结构伪装成用户输入。

Slide map input

采用哪种视觉语法？

这里选择的是公共版样式方向，不绑定任何公司模板。专有模板字段请放到 extensions 包。

Visual grammar
样式选择不会绕过验证。高可见度、自定义风格或 5 页以上 deck 默认先出代表性样张，再跑 `q-ppt-visual-review`。

检查 JSON 与交付门

导出的 JSON 是请求合同，不是最终故事、slide map 或 PPTX。后续步骤必须可追踪。

Needs input
1. Intake JSON静态页导出
2. Story briefAgent 创建
3. Slide map记录页数合同
4. PPTX生成或迁移
5. Visual review必须记录报告
6. Final open默认本地打开
下一步 补齐必填项后，下载 JSON，并把它交给支持 `q-ppt-intake/v1` 的 Agent 或本地 runner。浏览器静态页不会直接生成 PPTX。
