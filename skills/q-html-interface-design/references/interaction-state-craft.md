# Interaction-State Craft

Load this reference only for a visual study or higher with multiple
selection-oriented component families, an explicit high-fi/production state
craft goal, or feedback that active/current/selected treatment feels generic,
default, crude, or AI-made. It is an experimental quality rule: it governs the
meaning and hierarchy of state, not a house style.

## The Core Position

A selection is not a decorative condition. In a quality-critical interface it
changes the user's reading model: it narrows a scope, establishes a current
place, reveals a consequence, changes the priority of nearby information, or
prepares an action. A border, blue fill, underline, pill, checkmark, or icon
may support that meaning; none is a sufficient substitute for it.

Do not replace this rule with a global ban on blue, cards, underlines, borders,
or familiar controls. Those are materials, not evidence of taste. The question
is whether the chosen material is justified by the subject and works with the
rest of the state language.

## State Grammar Contract

Before component tokens, write a compact contract for each important
selection-oriented family:

| Family | Base | Hover | Focus | Selected / current | Disabled | Selection consequence |
|---|---|---|---|---|---|---|
| Example: evidence row | available context | intent to inspect | keyboard target | current evidence lens | unavailable source | evidence detail, counterpoint, and next verification become adjacent |

The contract is intentionally short. It must answer:

1. Which state has the strongest cue, and why is it the one that deserves it?
2. What two or more signals make a central choice legible? Choose from changed
   position/geometry, material contrast, relational linkage, information
   transformation, or action consequence.
3. How can `selected + focus` be recognized without creating two equal visual
   focal points?
4. What does disabled mean here, and how is it different from merely quiet?

Hover is a promise, not a commitment: it must remain weaker than selected or
current. Focus is an access signal and may coexist with selected; do not hide it
in the name of minimalism. Disabled is an unavailable action or path, not a
generic muted version of the normal item.

## Subject-Derived Selection

Use the content relationship to choose the visual language.

- A transcript segment can establish temporal continuity, playback location,
  and the supporting words around it.
- A configuration option can expose the hardware consequence and change the
  available next step.
- A research evidence decision can move the relevant counter-evidence and next
  verification beside the current judgment.

These are different selection consequences, so they should not inherit the
same stock accent, top line, or glow simply because all are controls. Keep
familiar interaction affordance, but derive the strongest cue and its nearby
relationship from the specific work.

## Collision Test

Test only the states relevant to the actual surface:

- `selected/current + focus`;
- a representative hover;
- one disabled or unavailable path;
- a narrow layout if the family survives on narrow screens.

Reject the component for this quality route if it shifts layout, relies solely
on color, covers content, makes disabled look normally actionable, or produces
two competing primary focal points. Motion can support an already-legible state;
it cannot be the sole cue or the evidence of hierarchy.

## Rendered State Specimen

For a quality-critical surface, capture a real detail specimen for two
representative component families and their relevant states. Whole-page
screenshots are not enough to score component precision. If selection is core
to the reading task, also create a same-viewport neutralized comparison: retain
the content and labels but remove the changed relationship or consequence. The
candidate should become materially less useful to scan or act on. If it does
not, return to the composition or content relationship rather than adding more
decoration.

The specimen is a strong default for visual studies. It is a hard blocker when
Xiao Q specifically criticizes state treatment as generic/default/crude, or for
a high-fi/production candidate with multiple selection-oriented families.

## Critique Ledger

Do not resolve a taste failure with the phrase "make it more premium." Record a
short chain instead:

`noticed -> cut or rebalance -> replacement relation -> rendered comparison -> verdict`

Example: `selection needed four unrelated markers -> remove tint, underline,
and shadow competition -> make the current evidence reorder its supporting
detail and next check -> compare against neutralized relation -> current state
remains legible without visual noise`.

## Research Boundary

This reference independently implements transferable mechanisms learned from
public frontend-design and design-skill research: establish a visual thesis,
make a deliberate composition tradeoff, critique rendered output, and avoid
mistaking a functional state for a finished state language. It does not copy
third-party prompts, prose, code, layouts, tokens, screenshots, logos, or
assets. Record source links and adaptation notes in the current project's
research ledger; no private maintainer study record is required.
