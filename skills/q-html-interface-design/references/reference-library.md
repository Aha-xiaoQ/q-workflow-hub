# HTML Design Reference Library

Use this library when a task needs visual calibration before building an HTML
tool, dashboard, diagram page, or personal website. These references are for
idea-level learning only unless a future task performs a separate license check.

## How To Use References

1. Pick 2-4 references maximum for a task: one structure reference, one visual
   style reference, one interaction/detail reference, and optionally one
   counterexample.
2. Extract traits, not assets: layout density, hierarchy, token shape,
   interaction rhythm, illustration role, component states, and responsive
   behavior.
3. Write an independent style brief before coding. Do not copy screenshots,
   CSS, code, component APIs, prompts, brand tokens, logos, illustrations, or
   proprietary visual identity.
4. For a personal website, translate references into a personal visual DNA:
   technical credibility, warmth/playfulness, reading rhythm, project proof,
   and navigation model.

## Anti-Patterns

- Do not copy a famous product's exact palette, mascot, layout, or copy voice.
- Do not let inspiration galleries replace usability validation.
- Do not mix multiple strong styles at once; choose one dominant direction.
- Do not use retro/pixel styling for dense forms unless readability remains
  better than the plain version.
- Do not use cartoon art to cover weak information architecture.
