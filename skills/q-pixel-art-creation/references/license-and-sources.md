# License and Source Boundaries

## Source roles

- `tutorial`: learn process and concepts; paraphrase mechanisms.
- `public preview`: observe visual mechanisms only; no asset reuse by default.
- `open asset library`: verify the exact asset license and attribution terms.
- `commercial game`: study general principles; never trace or ship a replica.
- `user-owned source`: exact reconstruction is allowed for the user's task,
  but still preserve original and refined versions separately.

## Non-shippable hard gate

Any close reconstruction made for learning is `non-shippable`. It may not be
placed in a game, site, release package, marketplace, or public repository until
all of these are true:

1. the exact source and license are recorded;
2. the intended use is compatible with that license;
3. attribution requirements are satisfied;
4. the asset is sufficiently original or explicitly licensed for reuse;
5. an independent reviewer confirms the shipping boundary.

If evidence is missing, keep the artifact private and use only the extracted
mechanism in a new original work.

## Learning record

Record source URL/file, author/site, observation date, license evidence, source
role, mechanisms learned, copied material (normally none), and shipping status.

Do not treat “free,” “downloadable,” “MIT repository,” a video description, or
a public web preview as a blanket license for every embedded image or asset.
