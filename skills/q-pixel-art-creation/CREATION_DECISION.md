# Creation Decision

- Decision: create `q-pixel-art-creation` as a new candidate skill.
- Why not an existing skill update: pixel-art study, reconstruction, native-size
  validation, action readability, provenance, and independent approval form a
  separate trigger and output contract. Game iteration consumes the result.
- Evidence: the C0-C4 2026-07-15 course exposed and closed repeated failures in
  effective resolution, contour construction, action skeletons, prop contact,
  and perceptual review.
- Approval-wait waiver: the user authorized a new pixel-character skill when
  needed (“如果像素角色需要建立一个新 skill 的话可以建一下”), required
  sedimentation after success (“成功之后记得沉淀 skill”), and repeatedly asked
  the loop not to stop for interim questions. The exact file plan was not shown
  as a separate approval card; therefore this is recorded as a current-thread
  approval-wait waiver, not as approval of a concrete file plan. The waiver is
  limited to a local `candidate`; it does not authorize stable/public release.
- Expert pre-review: Workflow Distiller GO with five P1 conditions; all five
  are represented in this candidate structure.
- Third-party posture: mechanisms only; no source code, prompt, coordinate,
  text, palette, or image asset copied into the skill.
