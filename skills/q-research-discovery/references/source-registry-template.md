# Source Registry Template

Use this when a source or query strategy is likely to be useful beyond the
current task. Store personal source registries in the user's private workflow
hub. Store only generic, public-safe examples in public repositories.

```markdown
### <Source Or Source Family>

- Useful for: <what future task this helps>
- Source role: <primary docs / public example / implementation reference /
  boundary source / counterexample / adjacent-domain source>
- Why it matters: <what pattern or decision it supports>
- Good queries:
  - `<query>`
- Evidence checked:
  - <source name or URL> - <what was verified>
- Adoption decision:
  - <learn pattern only / add template / use directly with attribution /
    defer / reject>
- Warnings:
  - <warning> - Severity: <blocking/degraded/informational/future risk>
- Last checked: <YYYY-MM-DD>
```

Keep registry entries short. If the research produced long notes, link to the
work item, project handoff, or generated artifact instead of copying everything
into the registry.
