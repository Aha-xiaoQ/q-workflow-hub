# Work Items

Create one markdown file per active or paused work item.

Suggested name:

```text
WI-YYYYMMDD-HHMM-short-name.md
```

## Brief Template

Use this shape when a task may need to survive a fresh session:

```markdown
# <Work Item Title>

Created: <YYYY-MM-DD>
Status: Active

## Objective

<What outcome should this work produce?>

## Current State

- Project/path:
- What exists now:
- What has already been tried:

## Constraints

- Permissions or risk boundaries:
- Privacy or public-safety notes:
- Tools, models, or providers:
- Validation expected:

## References

- Files:
- URLs or source ids:
- Screenshots or examples:

## Next Actions

1. <next concrete step>
2. <next concrete step>
3. <next concrete step>

## Recovery Notes

- <What a fresh session must know before continuing>
```

Keep it honest. Mark unknown facts as unknown or needing retest instead of
guessing. For real samples, record enough source and output detail that the
result can be recovered without rereading chat history.
